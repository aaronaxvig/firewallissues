## PANG-15020

In Strata Cloud Manager, when you open the Users panel from the Shared Workstation column in **Configuration** > **Endpoint Management** and the workstation has more than 10 users, the Users panel shakes or shifts horizontally. Additionally, clicking the Shared Workstation column header to group the devices with shared workstations does not change the sort order.

## PANG-15003

On Windows endpoints with Advanced DNS Security Resolver enabled, when the Prisma Agent tunnel is in connected internally, DNS queries that use TCP get no response and fail to resolve.

## PANG-15001

On macOS endpoints that use TCP-based DNS for bypass domains, the Prisma Agent traffic log can fill with many duplicate "Resolution of <hostname>" entries for the same host when Advanced DNS Security resolution is enabled on the tenant.

## PANG-14972

On a Windows endpoint, granular Peripheral Control policies for Endpoint DLP cannot differentiate between personal and work Google Drive accounts on the same endpoint. If conflicting policies are configured, such as blocking personal Google Drive accounts while allowing work accounts, the Prisma Agent applies the most restrictive forwarding rule (Block) across both account types. Users attempting to access a permitted Google Drive work account will be blocked if a separate Peripheral Control policy is set to restrict personal Google Drive accounts on the same device.

**Workaround:** Configure a unified Peripheral Control policy for Google Drive across all accounts on the endpoint, or avoid applying conflicting blocks and allow rules simultaneously for personal and work account profiles.

## PANG-14962

On Windows and macOS endpoints, when a Prisma Access gateway is configured to advertise public IPv6 addresses, Prisma Agent cannot establish IPsec or SSL tunnel connections to that gateway over the underlay (Physical) network. Endpoints running Prisma Agent will fail to connect securely to gateways advertising public IPv6 addresses, preventing network connectivity.

**Workaround:** Ensure Prisma Access gateways are configured to advertise compatible IPv4 addresses.

## PANG-14931

On Prisma Access dual-stack deployments where IPv4 and IPv6 DNS servers are assigned for the overlay (tunnel) connection, traffic routing for bypassed destinations is impacted on Windows endpoints. This affects both explicitly configured bypass rules in Forwarding Profiles and implicit bypass rules handled automatically by the Prisma Agent (such as Endpoint Manager traffic). Windows endpoints on dual-stack overlay networks may experience connectivity failures when trying to access bypassed destinations and critical agent communications.

**Workaround:** Configure the Prisma Access overlay (tunnel) connection to use only IPv4 DNS servers.

## PANG-14905

On Windows endpoints, when the tunnel disconnects and reconnects repeatedly in rapid succession, the Advanced DNS Security DNS-over-HTTPS (DoH) channel does not re-establish after the repeated transitions. DNS queries to the Advanced DNS Security server fail, and DNS resolution through Advanced DNS Security Resolver remains unavailable for the duration of the rapid cycling.

## PANG-11469

On macOS endpoints, the Prisma Agent service (PASrv) may intermittently consume high CPU resources for a short period, which causes macOS to generate a cpu_resource diagnostic report. The elevated CPU usage may affect battery life on laptop endpoints.
